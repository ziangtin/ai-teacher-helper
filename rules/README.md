# rules/

规则放这里。**一条规则一个文件**，文件名就是规则 id。

规则 = 跨任务都成立的红线与一致性要求（隐私、学术诚信、语气、未成年人保护……）。
只对某一个任务成立的约束不要写成规则，放进对应技能的「边界」里。

## 命名

`R-` + 大写下划线，例：`R-PRIVACY.md`、`R-ACADEMIC-INTEGRITY.md`。

## 格式

文件开头一段 YAML，后面三段正文：

```markdown
---
id: R-PRIVACY
title: 学生隐私与数据最小化
level: must
scope: [all]
---

## 要求

1. 一条一个编号，写成能判定对错的说法……

## 反例

- 真实会犯的错，不是假想的极端情况。

## 自检问句

1. 交付前用来自查的问句，能回答是/否。
```

| 字段 | 说明 |
| --- | --- |
| `id` | 与文件名一致 |
| `title` | 一句话标题 |
| `level` | `must` = 红线，不可违反；`should` = 默认遵守，偏离要说明理由 |
| `scope` | 适用范围，如 `all` / `k12` / `assessment` / `communication` |

## 两条硬要求

- **可判定**：写「不得出现学生真实姓名」，不写「注意保护隐私」。
- **给理由**：说明为什么，别只下命令——理解了才能在新情境里正确泛化。
