# skills/

技能放这里。**一个技能一个目录**，目录名就是技能名，技能本体是目录里的 `SKILL.md`。

技能 = 一件事怎么做（备课、出题、批改、学情分析、写评语、家长沟通……）。
受 `../rules/` 约束；规则与技能冲突时以规则为准。

## 目录结构

```text
skills/
└─ lesson-plan/            ← 技能名，kebab-case
   ├─ SKILL.md             ← 必需，技能本体
   └─ references/          ← 可选，按需读的补充材料
```

需要脚本、模板等附属文件时放在技能目录内（如 `scripts/`、`templates/`），
并在 SKILL.md 里写明什么时候用。

## SKILL.md 格式

开头一段 YAML，后面七个固定小节：

```markdown
---
name: lesson-plan
description: 一句话说明做什么、什么时候用
version: 1.0.0
categories: [k12, instruction]
triggers: [写一份教案, 帮我备课]
outputs:
  - 教案文档
rules: [R-AGE-APPROPRIATE, R-FACTUAL-ACCURACY]
---

## 适用场景
## 输入
## 流程
## 输出规范
## 质量自检
## 学科适配
## 边界
```

| 小节 | 解决什么 |
| --- | --- |
| 适用场景 | 什么时候用、什么时候不要用 |
| 输入 | 需要什么；缺了怎么问 |
| 流程 | 编号步骤，可执行 |
| 输出规范 | 长什么样 |
| 质量自检 | 交付前逐条能判定 |
| 学科适配 | 学科／学段差异 |
| 边界 | 何时停、何时问、何时拒 |

## 两条硬要求

- **流程**是可执行的编号步骤，不写「认真分析」这类空话。
- **自检**每条能回答是／否：「每条目标都含可观测的行为动词」可以，「目标写得好」不行。
